LOS 3 FORMATOS — EXPLICACIÓN BRUTAL Y SIMPLE
1) JSON
Es un formato estructurado tipo diccionario/lista.
Ventaja: lo puede leer cualquier programa, fácil de parsear.
Desventaja: no muestra jerarquías visuales bonitas; es más técnico.

Ejemplo:

{
  "Workspace": {
    "Camera": {},
    "Terrain": {},
    "Bases": {},
    "SpawnLocation": {
      "Decal": {}
    }
  }
}
Ideal si quieres que otra IA, script o herramienta entienda tu estructura.

2) YAML
Es como JSON pero más limpio, más humano.
Ventaja: se lee más fácil.
Desventaja: el indentado importa; un espacio mal puesto lo arruina.

Ejemplo:

Workspace:
  Camera:
  Terrain:
  Bases:
  SpawnLocation:
    Decal:
Esto es lo que usan sistemas grandes (Docker, Kubernetes, etc.).

3) Markdown jerárquico (listas sangradas)
Es el más cómodo para documentación.
Ventaja: se ve bonito, fácil de leer.
Desventaja: no sirve para scripts, solo para humanos.

Ejemplo:

Workspace
- Camera
- Terrain
- Bases
- SpawnLocation
  - Decal
Perfecto para Notion, Obsidian, GitHub READMEs.
